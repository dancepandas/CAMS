# CAMS 汇流感知多断面预报模型 · 交接文档

## 一、模型解决什么问题

一个共享权重的模型，同时预报流域内多条河流上多个断面的流量过程，预见期
若干小时。CAMS 的名字对应它的两个特点：

**汇流感知**。用高程算出的流向场划定每个断面的上游汇水区，做成掩膜，去
挑选降水网格中属于该断面的那部分。这样同一张降雨图在不同断面下变成不同的
输入——降雨落在哪里、上游汇了多少水，模型能直接看见，而不必从原始网格里
自己猜。这是它与普通时序预报模型的本质区别。

**多断面**。一套权重同时服务全流域所有断面。参考流域里十五个断面的集水
面积从十四平方公里到四千八百平方公里，跨三百四十倍，共用同一个模型。

## 四、快速开始

```bash
cd CAMS

# 全流程
python3 scripts/run_all.py

# 从某一步开始，或只跑某一步
python3 scripts/run_all.py --from catchments
python3 scripts/run_all.py --only train
python3 scripts/run_all.py --skip fetch_rain

# 临时覆盖参数
python3 scripts/train.py --set model.horizon=48 --set model.epochs=80
```

各步骤产物落盘，可以单独重跑，不会互相干扰。

## 五、数据来源

| 数据 | 来源 | 说明 |
|---|---|---|
| 降水 | MRMS MultiSensor_QPE_01H_Pass2 | 雷达与雨量计融合，约 1 公里，逐小时。取自爱荷华州立大学存档镜像 |
| 流量 | USGS 全国水情信息系统 | 参数代码 00060 瞬时流量，原始 15 分钟，取整点 |
| 高程 | SRTM 1 弧秒（约 30 米） | AWS 公开数据集 elevation-tiles-prod |

**换流域时的注意事项**：`fetch_rain.py` 里的网格换算公式是按 MRMS 美国本土
网格（3500 行 × 7000 列，左上角北纬 54.995、西经 129.995）写的，出了美国
必须换数据源并重写这段。流量与高程两家是分站/分图幅取的，换流域只需改配置
和站点表。

## 六、处理流程

**地形**（`terrain.py`）。四块 30 米图幅拼接后裁剪到配置范围，做填洼与 D8
流向计算，得到流向、汇流累积面积、坡度、河网级数。汇流累积面积是判断水往
哪里跑的直接依据，也是后面划汇水区的基础。

**汇水区**（`catchments.py`）。从每个断面出发沿流向反向追溯上游汇水范围，
再把 30 米二值掩膜按面积加权重采样到降水网格，得到每条断面在各网格格子上的
覆盖比例。

这里有个坑要留意：**必须逐个断面单独追溯**。如果把嵌套的多个出口一次性
交给划分函数，每个格子只会归给最上游的那个出口，下游断面的汇水区会被上游
切走——早期这么做时，阿什维尔只划出一百八十四平方公里，实际是两千四百四十七。

**面雨量**（`area_rain.py`）。按覆盖比例对降水网格做面积加权平均，得到每个
断面逐小时的面雨量序列。

## 七、模型结构

三路输入汇入一个共享的输出头：

```
历史流量 + 历史面雨量 ──→ LSTM（96 维隐状态）        ┐
预见期内的面雨量     ──→ LSTM（32 维隐状态）        ├──→ 全连接 ──→ 未来 H 小时
汇水区内多尺度累积降雨图 + 静态场 ──→ 卷积 ──→ 掩膜加权池化 ──┘
```

**空间分支**的输入是六张累积降雨图（1、3、6、12、24、72 小时）加上四张静态
场（汇水区掩膜、对数汇流累积、坡度、高程），过三层卷积后用汇水区掩膜做加权
池化。用掩膜池化是关键：它让特征只从该断面上游的区域里提取，而不是对全图
求平均。

**预见期降雨这一路不可省**。早期漏掉它时，模型只能靠历史外推，二十四小时
预见期下胜出持续性的断面数从十二个掉到零个。补上之后立刻恢复到十二个。

**目标值是逐站标准化后的对数流量**：每条序列先取对数，再减去本站训练期均值、
除以本站训练期标准差。这样各断面的目标分布一致，共享权重只需学一套映射。
模型预测的是相对窗口末刻的增量，持续性预报对应输出全零。

**损失用均方误差**。实测优于 Huber——后者对大偏差只给线性梯度，模型倾向报
保守值，输出的变率比会明显偏低。

## 八、训练与评估

按时间切分，前 70% 训练、次 15% 验证、末 15% 测试。测试段按预见期长度不
重叠采样。训练段按 `model.stride` 抽样以控制计算量。

评估同时看四个量：

- **纳什效率系数（NSE）**：全时段，但会被占九成时间的基流稀释；
- **KGE 及其三项分解**：相关性、变率比、偏置比。**变率比最能说明问题**——
  它衡量模型输出的波动幅度是否够，偏低就意味着洪峰被压平了；
- **洪峰时段 NSE**：取各断面最大的百分之十的窗口单独评估；
- **洪峰相对误差**。

只看 NSE 会被误导。参考流域上持续性预报的全时段 NSE 有 0.667，看着不低，
但它的变率比很差，洪峰完全报不出来。

## 九、当前性能

参考流域（法国布罗德，十五个断面，二〇二三至二〇二四两年，预见期二十四小时）：

| 指标 | 模型 | 持续性 |
|---|---|---|
| 中位 NSE | **0.772** | 0.667 |
| NSE 胜出断面 | **12/15** | — |
| 中位 KGE | 0.619 | 0.634 |
| 洪峰时段 NSE | **0.907** | — |

大集水面积的断面表现最好：纽波特 0.952、弗莱彻 0.933、阿什维尔 0.914、
马歇尔 0.900、温泉镇 0.886，都在持续性之上。小断面仍是短板，霍米尼溪 0.137、
比特里溪 0.390、米尔斯河 0.432。

## 十、已知限制

**预见期降雨用的是实测值**，相当于假设有一个完美的降雨预报。业务部署时这
一路要换成数值天气预报产品，其误差会顺着汇流放大，实际精度会低于离线评估。
**这是当前结果偏乐观的最大来源。**

**测试段与训练段存在量级外推**。参考数据里训练段到二〇二四年五月截止，测试
段从九月开始，海伦妮洪水正好落在缝里。个别断面测试期最大流量是训练期最大
值的数十倍，模型报不出没见过的量级，这是小断面洪峰低估的主因，属于训练数据
覆盖不足而非结构缺陷。扩长训练时段可以缓解——MRMS 从二〇一四年五月起可取。

**空间分辨率对小结面对不利**。一公里网格下，十几平方公里的集水区只有十几
个格子，卷积能提取的信息有限。若要改善，需把空间分支的网格加密。

**断面属性标量没有增益**。试过把集水面积、汇水区平均坡度与平均高程作为额外
输入，胜出断面数从十二掉到九。原因是流量序列本身已携带断面身份，汇水区掩膜
又给了一遍空间信息，标量属于重复投喂。该开关默认关闭（`model.use_site`）。

**只在单一流域验证过**，跨流域尚未涉及。

## 十一、后续可做

按优先级排列：

1. **扩长训练时段**。把降水历史推到二〇一四年，训练段覆盖更多大洪水，外推
   问题会明显缓解。降水下载约八万八千个文件，脚本带断点续传，挂着跑即可。
2. **接真实降雨预报**。把预见期的实测面雨量换成数值预报产品，才能得到有业务
   意义的精度估计。
3. **加密空间分支网格**。针对中小集水面积的断面，把 1 公里提到 250 米。
4. **跨流域验证**。当前架构是按单流域设计的，跨流域需要引入流域属性编码和
   量级归一化，是另一件事。

## 十二、复现性

全流程由随机种子 `model.seed` 固定，默认 42。训练在 CPU 上可复现，但 PyTorch
在不同硬件与版本下可能有微小数值差异。训练输出目录 `runs/site_model/` 内含
`best.pt`（权重）、`predictions.npz`（测试集预测）、`summary.json`（指标汇总）。
